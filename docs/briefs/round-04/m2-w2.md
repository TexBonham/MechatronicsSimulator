## Port

- `host_build.cpp`: process launch through `CreateProcessW` with a quoted command line (`cmake --preset host ...`),
  stdout and stderr captured through a pipe into the same log string the POSIX path produces, exit code from
  `GetExitCodeProcess`; a non-zero exit is the same `ControllerConfigError` text as on Linux.
- `native_controller_runtime.cpp`: `LoadLibraryW` / `GetProcAddress` / `FreeLibrary` behind the same RAII type the
  `dlopen` path uses; the per-load private copy keeps its semantics (copy the `.dll` to
  `<work_dir>/native-controller/<pid>-<n>/` and load the copy); error text from `GetLastError` through
  `FormatMessageW`; library file name `<app_target>_native.dll` (`lib...so` on POSIX) resolved by one helper used
  by the runtime, the tests and `core_wiring.py`.
- Fixtures: `mirror_app.cpp` exports its four entry points (`__declspec(dllexport)` under `_WIN32`, or
  `WINDOWS_EXPORT_ALL_SYMBOLS` on the fixture targets as the firmware already does); the reference native build
  test runs the real host configure on Windows the same way.
- Determinism and identity tests: if the archive identity differs across platforms, do not chase it in this brief;
  report the first differing attribute. The run-twice determinism test on the same runner must pass.
