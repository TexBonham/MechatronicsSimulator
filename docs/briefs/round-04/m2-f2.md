## 1. Serving (VIE-012)

`mechsim serve [--files-root PATH] [--runs PATH] [--port N]` starts the facade server on `127.0.0.1` and prints one
line `http://127.0.0.1:<port>/?token=<token>`; the server answers plain HTTP GET for `/` and the files under `web/`
(the `process_request` hook of `websockets`, same port; `index.html`, `*.js`, `*.css`, `vendor/*`; anything else
404; never a path outside `web/`), the WebSocket on `/ws?token=`. The token is read by the client from its page
URL and put on the socket URL; a wrong token is refused at the handshake as today. Tests: the route serves
`index.html` and a vendored file, refuses `..` and absolute paths, 404 for unknown, the CLI prints the URL and exits
0 on `--check` (starts and stops without serving) so the test needs no browser.

## 2. Client (VIE-001, VIE-002, VIE-015, FAC-016, FAC-019)

`web/index.html`, `web/app.js`, `web/protocol.js` (envelope, version, message ids, request/response matching, the
`tick_batch` header plus `ArrayBuffer` to `Float64Array` columns), `web/replay.js` (3D replay with three.js,
vendored as `web/vendor/three.module.js` at one pinned release; record the version and its SHA-256 in
`web/README.md`; no CDN at runtime), `web/timeline.js` (event marks from `timeline`), `web/probes.js` (probe panel from
`probe` and `value_at`). The client: lists designs and runs, opens a replay (`replay_open`), draws every body from
`geometry` (box, sphere, capsule, cylinder, plane by their sizes; convex hull as its vertices), poses bodies from
`subscribe_series` over the pose series for the cursor window, scrubs, pauses, steps, shows the timeline and a
probe's values. Every number shown comes from a facade message: no physics, scoring or unit conversion in
JavaScript (FAC-016); SI values displayed with the unit the message names. Determinism: the client never writes
files (VIE-017) and holds no design-specific names (invariant 2).
