## Items (integrity: write the failing test from the closed form first)

1. Design-load factor applied twice (ruling 52): the post-run table scales every recorded load by the design's
   allowance (`mechsim/integrity/inputs.py`, about line 284) while G15's payload already carries the design
   load. Add a case field stating that the run carries the design load (then the factor is 1 and a line says
   so); default: the table applies the design's rule as today. Tier 1 never scales (unchanged). Tests for both
   states; the INT and TST rows state which tier scales when.
2. Strength from the peak moment along the member (INT-005, INT-023): the tier 2 check reads end moments only,
   so a pinned-roller rail under a mid-span load reads a safety factor of 9.4 where the mid-span moment gives
   1.56; the tier 1 party adds one resolved interior point and over-reads (review: about 10.0 MPa against 8.78
   true on rail_y). Both tiers take the bending moment at every node from the node springs: (E I / l) times the
   relative rotation of adjacent node bodies about the bending axis, from the recorded (tier 2) and published
   (tier 1) node poses, plus the end moments; stress M c / I with the section's fibre distance for that axis.
   Oracles, each within the lumped chain's 2 percent row at the stated segments: pinned-pinned centre load
   M = P L / 4; a load at a: P a b / L under the load; cantilever tip load P L at the root; clamped-clamped
   centre load P L / 8 at the ends and at the centre; uniformly distributed own weight w L^2 / 8 (pinned) and
   w L^2 / 12 at the ends (clamped). The two tiers agree on the same run within 1e-9 relative. A rigid member
   stays not-evaluated.
3. The post-run fastener check produces no rows on the gantry: it skips mounts (`checks/fastener.py`, about line
   37) while tier 1 includes rated mounts. One rule for both, from one place; test on a design with a rated
   mount and a rated fastening.
4. Evaluation start (TST-041 neighbour): a case field for the time from which integrity results count (peaks,
   safety factors, tier 1 crossings), default the start of the run; published as a line; a crossing before it is
   recorded as an event but does not fail the case. This exists because a run starts with straight members and
   their release transient is not a load case (a static start is milestone 4). Tests in both tiers.
5. Gantry cases and tests (from the review):

     changed (rail height, frames): regenerate those entries on the bridge and show in the report that every

   - BLD-039: the bridge's stand-in line is emitted only when a payload is attached; G3 has none. Use a case
     with an attached payload (G5, G7 or G9), convert the stub.
   - ACC-025: the row claims 2 a / g on the first ramp and the run exceeds it by 1.2 percent because the trolley's
     real acceleration is above nominal early in the ramp; the bound uses L = 0.3 m for a pendulum of about
     0.37 m (rope plus fittings to the payload's centre). State the bound with the real length and assert the
     hook's recorded acceleration against a derived allowance (what the drive's lag permits), so the swing bound

   - ACC-029: the stress assertion is one-sided; make it two-sided against the oracle so a false pass cannot
