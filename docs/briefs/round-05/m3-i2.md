## Deliverables, in order

1. Limits table (INT-023, invariants 2 and 3): `mechsim/integrity/tier1.py` builds, from the `BuildResult` and the
   `integrity.yaml` beside the design (ruling 27), one record per member (section A, I_y, I_z, c_y, c_z, length,
   segment length, support condition and effective length factor K as I1's buckling check uses them, E, the
   allowable stress = the conservative (minimum-spread) strength through `IntegrityMaterialView` at the run's
   ambient temperature for the member axis divided by the minimum safety factor, the yield strength itself, the
   deflection limit) and one per rated fastening (rating from configuration; a fastening named by the tier 1
   fastener check without a rating is a build error). Serialised to the party as JSON; nothing design-specific in
   C++. No `integrity.yaml` or tier 1 not enabled in it: no party registered, every existing run unchanged.
2. The party (INT-023): `core/integrity/` `IntegrityParty`, a kernel `Party` at the physics rate consuming
   `physics.outputs`. Every tick, per member, from the published end wrenches in the member frame (ruling 24):
   stress |N|/A + |M_y| c_z/I_y + |M_z| c_y/I_z at each end and at the interior point I1's `beam.py` resolves, the
   same formula as I1 (state it in the contract); buckling margin P_cr / P for a compressive axial load with
   P_cr = pi^2 E I_min / (K L)^2; deflection by I1's static end-load formula (ruling 28); per rated fastening the
   constraint force magnitude against its rating. Oracles (derive, do not read from the implementation): a
   cantilever of length L with a tip load ramping as P(t) = k t crosses the allowable stress at
   t* = sigma_allow I / (k L c), so the event tick is the first tick with t > t* (strict crossing; test the tick
   before and the tick of); a pinned-pinned column under a ramping axial load crosses margin 1 at
   t* = pi^2 E I / (k L^2); a fastening under a ramping load at t* = rating / k. Cross-check: on one recorded run,
   the party's peak stress per member equals I1's post-run peak (`mechsim/integrity/checks/strength.py`) to 1e-9
   relative.
3. Crossings (INT-024, INT-025, INT-027): the first crossing of each (member or fastening, quantity) raises one
   event stamped with that tick's simulated time (ruling 34: one event per pair per run, no re-arm); kind and
   source `integrity`, detail `IntegrityCrossing.detail()` with tier 1 (ruling 26), through the recorder so SCO-015
   fails the case with no scoring change. Determinism: the same design, case, seed and mode give the same events
   at the same times (run twice, compare the event lists bitwise).
4. Halt (INT-026, ruling 4): test-case field `integrity.halt_on_crossing`, boolean, default false, in the case
   schema with its example and tests (absent, false, true, wrong type); true ends the run at the crossing tick
   through the kernel's `party_state` end trigger with end reason stated in the report, false lets it run to its
   end; the case fails either way.
5. Tier 2, milestone 3 (ruling 3; INT-028 and INT-031 move from M4 to M3 in their rows): enabled per check in
   `integrity.yaml` (tier 2), additive (a tier 2 run's tier 1 events equal the tier 1 run's up to the first model
   change: test it).
   - Yield (INT-028, ENG-031): ruling 35, a stated placeholder plasticity rule. At the member end with the larger
     bending moment, the node spring nearest that end carries the moment M_n the end wrench gives by statics over
     the half segment (derive it; neglecting that half segment's inertia is the stated approximation). With
     M_y = sigma_y I / c and k = E I / l (l the segment length), the permanent offset requested is
     phi = sign(M_n) (max over the run so far of |M_n| - M_y) / k when positive: it grows only when the peak grows,
     so it is bounded and deterministic. Oracle: a cantilever loaded at the tip to P > M_y / (L - l/2) and
     unloaded keeps a tip displacement (L - l/2) sin(phi) with phi from the peak (E2's offset semantics, ENG-031
     row). Each change of the offset is one event of kind `model_change` (never `integrity`, ruling 26), and one
     approximation line per run names the rule.
   - Rope snap (INT-031, ENG-034): the engine snaps a rope over `breaking_tension` and lists `RopeSnapped` then
     `LoadReleased`; show both reach the recorder as `model_change` events at the snap tick and the load falls
     free afterwards (acceleration g within the reference tolerance); no party logic beyond routing.
   - Transport: the party publishes its requests as a coupling variable the physics party consumes and applies
     through the adapter's mid-run entry (PHY-008) before its next step; unwired when no party is registered
     (KER rows: say which).
6. Adapter scope: tier 1 needs lumped members, so on the bridge (`rigid_members=True`, ruling 29) the party is not

   adapter it runs.
