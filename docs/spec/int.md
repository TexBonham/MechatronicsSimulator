# Spec: Mechanical integrity (INT)

## Purpose

Mechanical integrity (`mechsim/integrity/`) checks whether a design's members, mounts, fasteners and bearings survive
the loads a run produces: data-driven, tiered check plugins, each with an analytical reference, evaluated after a run
from the recording and, for tier 1, every tick inside the kernel. It exports load cases and imports FEA results. Its
scope is mechanical integrity, not finite-element structural analysis, which the engine and external tools cover.

"Architecture doc" below is `docs/Mechatronic Simulator — Architecture and Technology Recommendation.md`;
"Requirements doc" is `docs/Mechatronic Simulator — Requirements.md`.

spike, phase 1, or roadmap; "spike" is the calibration spike before phase 1 (R-12): engine packages 1 and 2 plus their
analytical references. Tier: unit, reference, acceptance or invariant. Tolerance: a value with its unit, "<value>
(<qualifier>)", "identical", "bitwise identical", "n/a", "not set (owed by <who>)", or "not set (owed by <who>,
proposed <value>)".

## Check rules (brief I1, milestone 3)

| Topic | Rule |
|---|---|
| Configuration (INT-002) | `integrity.yaml` beside the design's `design.yaml` (ruling 27; `schemas/integrity.json`, worked example `schemas/examples/integrity.yaml`, file kind `integrity` for `validate`): `schema_version` 1, `checks` (each `check`, fidelity `tier`, `parameters`; the entry `rope_snap`, tier 2 only and without parameters, gates INT-031), `thermal` (INT-036 slot). Halting is the test case's field only (rulings 4, 50); a `halt_on_crossing` key here is refused. Absent file: the run carries no table. Strength and deflection always run when the file is present (the table needs them). |
| Plugins and tiers (INT-001, INT-003) | A check is a module under `mechsim/integrity/checks/` defining `CHECK` (or an entry point in group `mechsim.integrity_checks`); its schema entry is generated from its parameters model. "Tier" is the fidelity tier: a higher tier adds rows and leaves lower-tier rows unchanged. Strength tier 2 adds average shear V / A and von Mises sqrt(sigma^2 + 3 tau^2). |
| End-loads (ruling 24) | Member frame, x from start to end, y and z the principal axes; each end's wrench is the load applied to the member there, so internal axial force is -F_start.x and +F_end.x (tension positive). |
| Design load (INT-019, TST-043, ruling 52) | Post-run (tier 2 table): recorded loads times 1 + `structural.design_load.allowance` from the design file (the run is taken to carry the rated load); 1 when the design has no `structural` section, and 1 when the case states `integrity.design_load_carried: true` (its payload already carries the design load), with the note `design load: the case carries it (integrity.design_load_carried), so the table applies factor 1, not the design's rule (TST-043, INT-019, ruling 52)`. Table values are at the design load. Tier 1 never scales (live loads). The rope table's `design_load` flag keeps the rule's weight either way. |
| Strength (INT-005) | Per end and sample abs(N) / A + abs(M_y) c_z / I_y + abs(M_z) c_y / I_z (ruling 25, member frame of ruling 24, the same formula as the VIE-010 overlay); for a lumped member also at every node spring (brief M3-I4): M_z = k times the rotation about z of the spring's node body relative to the body before it (a clamped root's node 0 against the root frame, the parent's recorded pose times the member placement; a pinned root's node 0 is the spring-free pin segment, so its springs start at node 1), k = E I / l of the simulated section, from the recorded node poses (tier 1: the published ones); abs(N) there the larger end value; M_y interpolated linearly between the end moments (the chain is rigid out of its bending plane, ruling 65); the peak over the ends and the springs. A member without node poses (the bridge) reads its ends only, with the note `strength of '<m>': end moments only, the member has no node poses (INT-005)`; a yielded spring reads k times its elastic rotation, the total minus the yield offset in effect (INT-028, ruling 35: tier 1 the offsets the party requested, from the tick after each request; tier 2 the recorded `model_change` events `spring_offset spring <i> value <v>`, absolute, from the row that lists them, the spring order of the native adapter). On a member that carries a joint (the neutral member's `carries`, ENG-052) also the moment under the carried load between two samples (brief M3-I4b, ruling 71; derivation `mechsim/integrity/beam.py`, section "Moment under a carried load"): samples s_0 = 0 (M = -M_z0), the springs, s_{N+1} = L (M = M_z1); per segment the intersection of the line through the two samples before it and the line through the two after it (at the start the start wrench's line, value -M_z0, slope F_y0; at the end the end wrench's, value M_z1, slope -F_y1), a candidate when the slopes differ and it lies strictly inside the segment, with abs(N) the larger end value and M_y interpolated there. Exact for one point load in a segment of a statically determinate member (pinned or roller ends: the reactions take the lever share at the end node; a free tip's line is M = 0); a clamped root's stub [0, l / 2] belongs to the parent, so a load there is read at the clamp from the first spring's line (limitation); conservative for one sign of load distributed in a segment; own weight on a carrying member reads w L^2 / 8 (1 + 3 / N^2) at most (the neighbours' secants: +4.7 percent at N = 8, +1.2 percent at N = 16); a load inside a clamped root's stub [0, l / 2] under-reads the clamp by at most F l / 8 (its lever share w_0 F s, s (l / 2 - s) / (l / 2) at most l / 8). Not resolved by the rule, bounded instead (brief M3-I5, ruling 72; derivation `mechsim/integrity/beam.py`, section "What the carried-load rule does not resolve"): a carried couple C (C = M_p . z rebuilt per row from the recorded joint reaction of the carried body, the engine's carried output s, F . y, M_p . z being unrecorded; the larger of the row's and the previous row's value, the engine applying the previous step's reaction; a couple below 1e-9 |F| L counts as none): U = |C| for one carried load in a segment with unloaded neighbours (C b / L is not a bound on the read's error: at N = 8 the read falls short by up to 1.015 |C| b / L); several carried loads in a segment of opposite sign or with a couple, or a carried load whose neighbouring segment holds one too: U = sum |F_i| h / 4 + sum |C_i| (chord bound). The strength row then reads each sample's peak plus U c_y / I_z at the design load, carries detail `unresolved_moment` (N m) and `unresolved_stress` (Pa), its safety factor is taken on it, and the report carries the line `strength of '<m>': conservative, ...` naming the cause; tier 1 does not add the bound (open). A member carrying nothing is unchanged to the last bit. Tier 2 von Mises at a spring takes the larger end shear (a single-signed transverse load keeps the shear between its end values). Oracles (`tests/reference/test_integrity_checks.py`): pinned centre load P L / 4 (N = 9), a load at a P a b / L (N = 8, a = 2.5 l) and own weight w L^2 / 8 pinned (N = 9), statically determinate, within theta^2 relative (theta the largest slope: the second-order arm change of the deflected loads, brief M3-I5); carried couple (pinned, N = 8, a = 0.2 m on L = 0.5 m, P = 30 N, push 400 N at d = 0.02 m, both signs): conservative read at or above the true peak P a b / L + C b / L and within |C| of it, the plain read below it; opposite loads in one segment and in neighbouring segments at or above the true peak; within the lumped chain's 2 percent: cantilever tip load P L at the root, clamped-clamped centre load P L / 8 at the ends and the centre (N = 17) and w L^2 / 12 at the clamped ends (N = 16); tier 1 on the same end-loads and poses within 1e-9 relative. Carried load (ruling 71; the data-only carried bar, N = 8, carried minus carrying nothing): pinned-pinned P a b / L at a = 0.1, 0.3125, 0.5, 0.77 L within 1e-9 relative of the chain statics; clamped-clamped at 0.5 L, P L / 8 within the 2 percent row; own weight on a carrying member w L^2 / 8 (1 + 3 / N^2) at N = 16 within 1e-6 and inside the row; a member carrying nothing bit for bit the I4 formula; the two tiers within 1e-9; a yielded spring: k times the elastic rotation equals the root joint's statics within 1e-9 at every row after the offset. Section values: I_z the section's `second_moment_of_area`, I_y `second_moment_y`, c_y `fibre_y`, c_z `fibre_z`; a section missing any y-axis field is evaluated with I_y = I_z and c_y = c_z = the stated fibre or sqrt(3 I / A), and its table row carries the flag `approximation: single-axis section`, never refused; safety factor = yield strength spread along the member axis at the ambient temperature over the peak; the axis is the lumped member's placement x (parent frame, the rotation the recorder's member frame uses, ruling 24), body x for a member without a lumped record (rigid build). Mounts: abs(F) / A + abs(M) max(c) / min(I) of the joint reaction on the held member's section (plate theory owed: no mount sections yet). |
| Deflection (INT-006, INT-021) | From the recorded node poses of the member's lumped chain (ruling 28, brief X1b; `physics/bodies/*`, the native adapter publishing each lumped member's node bodies after the neutral bodies, root to tip): per sample the largest perpendicular distance of the node origins and the far end (the last node's origin plus l / 2 along its x) from the reference line, peak over the run, times the design-load factor (linear elasticity, INT-019), against `structural.accuracy_target`. Reference line: a member with a clamped root (cantilever, clamped-clamped) uses the root tangent, the parent body's recorded pose times the member placement, through the root point along its x (for a cantilever the chord through both ends is not the undeformed axis); a pinned root (pinned-roller) uses the chord from the pin (node 0) to the far end. The value is the measured pose, dynamics included: a static deflection is read from a settled run. A member built rigid (the MuJoCo bridge) has no nodes: its row is not evaluated (value NaN, never zero, flag `deflection_not_evaluated`) and the report carries the note `deflection of '<member>': not evaluated, the member is built rigid and has no node poses (INT-006)`, folded into the rigid-build line (next row) when the member also has no recorded end-loads. Node indexing is checked (brief X1c): a member's parent is the world or a neutral body, and an unknown parent or one naming another member's node (`<member>.node<k>`) is an `IntegrityError`, never the world; the node bodies and the parent are found by the published body `names` (`<member>.node<k>`, in order): tier 2 the recorder's, tier 1 the prepared native model's (its neutral bodies, those a case adds at run time such as a payload and its shackle included, then each member's nodes; brief I3), so run-time bodies shift no index; with names every body of the build must be among them, else an `IntegrityError` naming the missing ones, and the recorded body count per sample must equal the names; a recording without names falls back to the build's layout, whose count must equal the neutral bodies plus every member's nodes, else an `IntegrityError` naming both counts; the tier 1 table states the exact published body count (`bodies`) and the party faults on any other count, never an upper bound; a run with flexible members that recorded no body poses is an `IntegrityError`, distinct from a member built rigid. The per-sample deflection rides with the check's result so scoring can read the history (SCO-028). |
| Rigid build (INT-005, INT-006; rulings 29, 34, 60; brief I3) | A member built rigid (the build has a physics model and no lumped record for it, BLD-033: the MuJoCo bridge) whose run recorded no end-loads is not evaluated by any check that reads end-loads or node poses: strength (each quantity of the tier), buckling, fatigue and impact give one row per quantity with value NaN, never zero, flag `end_loads_not_evaluated`; deflection its `deflection_not_evaluated` row; the table's peak stress and safety factor are NaN; the report carries one note per member, `member '<m>': <checks> not evaluated, the member is built rigid and the run recorded no end-loads or node poses (rulings 29, 34)`; the load case leaves the member out. The run and the criteria that do not read these quantities are unaffected; a structural criterion reading one is an unevaluable error (SCO-029). Mount rows read the joint reaction and are evaluated. A rigid member with some but not all of its end-load series recorded is a partial recording, an `IntegrityError` naming the series it has and lacks (brief I3b). A flexible member, or a build without a physics model, with no recorded end-loads is an `IntegrityError`. |
