# Spec: Mechanical integrity (INT)

## Purpose

Mechanical integrity (`mechsim/integrity/`) checks whether a design's members, mounts, fasteners and bearings survive
the loads a run produces: data-driven, tiered check plugins, each with an analytical reference, evaluated after a run
from the recording and, for tier 1, every tick inside the kernel. It exports load cases and imports FEA results. Its
scope is mechanical integrity, not finite-element structural analysis, which the engine and external tools cover.

"Architecture doc" below is `docs/Mechatronic Simulator — Architecture and Technology Recommendation.md`;
"Requirements doc" is `docs/Mechatronic Simulator — Requirements.md`.

## Requirements

Requirement: one shall-statement. Source: a document and section, an ADR, or a ruling ID. Milestone: M1 to M5,
spike, phase 1, or roadmap; "spike" is the calibration spike before phase 1 (R-12): engine packages 1 and 2 plus their
analytical references. Tier: unit, reference, acceptance or invariant. Tolerance: a value with its unit, "<value>
(<qualifier>)", "identical", "bitwise identical", "n/a", "not set (owed by <who>)", or "not set (owed by <who>,
proposed <value>)".

## Check rules (brief I1, milestone 3)

| Topic | Rule |
|---|---|
| Configuration (INT-002) | `integrity.yaml` beside the design's `design.yaml` (ruling 27; `schemas/integrity.json`, worked example `schemas/examples/integrity.yaml`, file kind `integrity` for `validate`): `schema_version` 1, `checks` (each `check`, fidelity `tier`, `parameters`; the entry `rope_snap`, tier 2 only and without parameters, gates INT-031), `thermal` (INT-036 slot). Halting is the test case's field only (rulings 4, 50); a `halt_on_crossing` key here is refused. Absent file: the run carries no table. Strength and deflection always run when the file is present (the table needs them). |
| Plugins and tiers (INT-001, INT-003) | A check is a module under `mechsim/integrity/checks/` defining `CHECK` (or an entry point in group `mechsim.integrity_checks`); its schema entry is generated from its parameters model. "Tier" is the fidelity tier: a higher tier adds rows and leaves lower-tier rows unchanged. Strength tier 2 adds average shear V / A and von Mises sqrt(sigma^2 + 3 tau^2). |
| End-loads (ruling 24) | Member frame, x from start to end, y and z the principal axes; each end's wrench is the load applied to the member there, so internal axial force is -F_start.x and +F_end.x (tension positive). |
| Design load (INT-019) | Recorded loads times 1 + `structural.design_load.allowance` from the design file (the run is taken to carry the rated load); 1 when the design has no `structural` section. Table values are at the design load. |
| Strength (INT-005) | Per end and sample abs(N) / A + abs(M_y) c_z / I_y + abs(M_z) c_y / I_z (ruling 25, member frame of ruling 24, the same formula as the VIE-010 overlay; I_z the section's `second_moment_of_area`, I_y `second_moment_y`, c_y `fibre_y`, c_z `fibre_z`; a section missing any y-axis field is evaluated with I_y = I_z and c_y = c_z = the stated fibre or sqrt(3 I / A), and its table row carries the flag `approximation: single-axis section`, never refused); safety factor = yield strength spread along the member axis at the ambient temperature over the peak; the axis is the lumped member's placement x (parent frame, the rotation the recorder's member frame uses, ruling 24), body x for a member without a lumped record (rigid build). Mounts: abs(F) / A + abs(M) max(c) / min(I) of the joint reaction on the held member's section (plate theory owed: no mount sections yet). |
| Deflection (INT-006, INT-021) | From the recorded node poses of the member's lumped chain (ruling 28, brief X1b; `physics/bodies/*`, the native adapter publishing each lumped member's node bodies after the neutral bodies, root to tip): per sample the largest perpendicular distance of the node origins and the far end (the last node's origin plus l / 2 along its x) from the reference line, peak over the run, times the design-load factor (linear elasticity, INT-019), against `structural.accuracy_target`. Reference line: a member with a clamped root (cantilever, clamped-clamped) uses the root tangent, the parent body's recorded pose times the member placement, through the root point along its x (for a cantilever the chord through both ends is not the undeformed axis); a pinned root (pinned-roller) uses the chord from the pin (node 0) to the far end. The value is the measured pose, dynamics included: a static deflection is read from a settled run. A member built rigid (the MuJoCo bridge) has no nodes: its row is not evaluated (value NaN, never zero, flag `deflection_not_evaluated`) and the report carries the note `deflection of '<member>': not evaluated, the member is built rigid and has no node poses (INT-006)`, folded into the rigid-build line (next row) when the member also has no recorded end-loads. Node indexing is checked (brief X1c): a member's parent is the world or a neutral body, and an unknown parent or one naming another member's node (`<member>.node<k>`) is an `IntegrityError`, never the world; the node bodies and the parent are found by the published body `names` (`<member>.node<k>`, in order): tier 2 the recorder's, tier 1 the prepared native model's (its neutral bodies, those a case adds at run time such as a payload and its shackle included, then each member's nodes; brief I3), so run-time bodies shift no index; with names every body of the build must be among them, else an `IntegrityError` naming the missing ones, and the recorded body count per sample must equal the names; a recording without names falls back to the build's layout, whose count must equal the neutral bodies plus every member's nodes, else an `IntegrityError` naming both counts; the tier 1 table states the exact published body count (`bodies`) and the party faults on any other count, never an upper bound; a run with flexible members that recorded no body poses is an `IntegrityError`, distinct from a member built rigid. The per-sample deflection rides with the check's result so scoring can read the history (SCO-028). |
| Rigid build (INT-005, INT-006; rulings 29, 34, 60; brief I3) | A member built rigid (the build has a physics model and no lumped record for it, BLD-033: the MuJoCo bridge) whose run recorded no end-loads is not evaluated by any check that reads end-loads or node poses: strength (each quantity of the tier), buckling, fatigue and impact give one row per quantity with value NaN, never zero, flag `end_loads_not_evaluated`; deflection its `deflection_not_evaluated` row; the table's peak stress and safety factor are NaN; the report carries one note per member, `member '<m>': <checks> not evaluated, the member is built rigid and the run recorded no end-loads or node poses (rulings 29, 34)`; the load case leaves the member out. The run and the criteria that do not read these quantities are unaffected; a structural criterion reading one is an unevaluable error (SCO-029). Mount rows read the joint reaction and are evaluated. A flexible member, or a build without a physics model, with no recorded end-loads is an `IntegrityError`. |
| Buckling (INT-007) | Peak compression over the run against pi^2 E I_min / (K L)^2, K 2 (clamped-free), 1 (pinned-pinned), 0.5 (clamped-clamped), 0.699 (clamped-pinned), or the configured override. |
| Fatigue (INT-008, INT-037) | Rainflow on the signed normal stress at the four corners of each end section; Miner sum against the S-N curve (log-log; infinite life below its last amplitude; first sloped segment extended above its first); flagged at `damage_limit` (default 1, Miner). The governing history's cycle count is recorded. |
| Fastener (INT-010) | Peak joint reaction force against the rating in `ratings` (catalog grade ratings owed); margin rating / peak, flagged below the minimum safety factor (1 when the design sets none). |
| Impact (INT-011) | An event is a rise of a member's largest end force (or a mount's reaction) by more than `step_threshold` between samples, one per `window`; peak stress over the window times `impact_factor` against ultimate strength. |
| Resonance (INT-012) | First frequency: the calibrated value (BLD-019), else lambda^2 / (2 pi L^2) sqrt(E I_min / (rho A)) for the end conditions; each configured series gives f = abs(value) `hz_per_unit`; flagged when any sample is within `band` f_n. |
| Tier 1 party (INT-023, rulings 5, 24, 25, 27, 34) | `core/integrity/` `IntegrityParty`, registered after physics at the physics rate on the native adapter only (lumped members, ruling 34; on the bridge the run carries the approximation line `integrity tier 1: not evaluated ...` and no party). On when `integrity.yaml` lists `strength` (stress), `buckling` (buckling margin), `deflection` or `fastener` (fastener load); absent file or none listed: no party, the run unchanged. Limits table from `mechsim/integrity/tier1.py` (JSON, format `mechsim-integrity-limits-1`): per member A, I_y, I_z, c_y, c_z, L, E, K (I1's buckling rule or the configured override), allowable stress = minimum-spread yield strength along the member axis at the ambient temperature over the minimum safety factor (1 when the design sets none), the yield strength, the deflection limit (`structural.accuracy_target`), supports, first node spring, N, l, k; per rated fastening (every `fastener` fastening, which must have a rating, and any mount given one) the neutral joint and rating over the minimum safety factor. Live loads, no design-load factor. Per tick per member, from the end wrenches in the member frame: stress abs(N) / A + abs(M_y) c_z / I_y + abs(M_z) c_y / I_z at each end and at each bending plane's resolved interior point (I1's `_plane`; abs(N) there the larger end value), the largest; buckling margin pi^2 E I_min / (K L)^2 over the compression max(F_start.x, -F_end.x) when positive; deflection from the published node poses by the rule of the Deflection row (live, no design-load factor; the limits table carries each member's `nodes`: `first_body`, `count`, `root`, `parent_body` (null: world), `position`, `orientation`, or null for a member without nodes, whose deflection the party leaves unevaluated); per fastening the joint reaction force magnitude. Crossing strictly past the limit (stress, deflection, load above; margin below the minimum safety factor). |
| Tier 1 events (INT-024, INT-025, INT-027, rulings 26, 34) | The first crossing of each (member or fastening, quantity) raises one event, no re-arm: source and kind `integrity`, time the row's (the state the outputs hold), detail `IntegrityCrossing.detail()` with quantity `stress`, `buckling_margin`, `deflection` or `fastener_load`, tier 1; in the recording through the row, so SCO-015 fails the case. Same design, case, seed and mode: the same events at the same times. |
| Halt (INT-026, rulings 4, 50, 51) | Test-case `integrity.halt_on_crossing`; absent section, empty section or false: the run continues to its end and the case fails on the crossing (INT-025); nothing else sets it (no `integrity.yaml` fallback). True: the party reports finished and the kernel's `party_state` trigger ends the run at the crossing row with end reason `integrity_halt` (driver `EndReason`, archive `end_reason`, facade `RunEndReason`), scored as a failed case, and the report carries the note (not an approximation) `integrity halt: the run ended at <t> s on the <quantity> of '<member or fastening>' at <value> against the limit <limit> at <t> s (INT-026)` (`RunReport.notes`, archive key `notes`). |
| Tier 2 yield (INT-028, ruling 35) | On with `strength` at tier 2. At the member end with the larger abs(M_z) (the start on a tie) the nearest node spring (x = l / 2 or L - l / 2) carries M_n = -M_z0 + (l / 2) F_y0 (start) or M_z1 + (l / 2) F_y1 (end), statics over the half segment, its inertia neglected. With M_y = sigma_y I_z / c_y and k = E I / l (the lumped record's node stiffness), when max over the run of abs(M_n) at that spring grows past M_y the party requests the offset sign(M_n) (peak - M_y) / k, M_n the moment of the tick the peak grows (ruling 35 placeholder: a larger reversed peak replaces the offset with its own sign; no request while abs(M_n) stays at or below the running peak) (`integrity.model_requests`, applied by the physics party before its next step, KER-028); each change is one `model_change` event from the adapter's listing, never `integrity` (ruling 26); the run carries the approximation line naming the rule. Planar bending about member z (the engine's lumped beam). Additive: a run's tier 1 events equal the tier 1-only run's up to its first model change. |
| Tier 2 rope snap (INT-031, ENG-034, ADR 0016, ruling 53) | On with the `rope_snap` entry (tier 2) in `integrity.yaml`; absent file or entry: the driver drops every rope's `breaking_tension` from the run's model and the run carries one approximation line per rope that stated one (`integrity tier 2 rope snap: off ...`), so no rope snaps. On: the engine snaps a rope over `breaking_tension` and lists `RopeSnapped` then `LoadReleased`; both reach the recorder as `model_change` events in the snap tick; integrity adds nothing but the routing. |
| Rope table (INT-022, ADR 0016) | One `RopeIntegrity` row per rope of the model: peak of the recorded largest segment tension (`physics/ropes/max_tension`) and its time; flag `snap` above the rope's `breaking_tension` (absent: never, ruling 19), flag `design_load` above rated_load (1 + allowance) abs(g) when the design states the design-load rule. Reference: a hanging mass at m g, proposed 1e-9 relative. |
| Flags and table (INT-020 to INT-022) | Flags: `safety_factor_below_minimum` (minimum-strength safety factor), `deflection_over_target`, `buckling_margin_below_minimum`, `impact_margin_below_minimum` (impact rows only), `fatigue_damage_over_limit`, `fastener_margin_below_minimum`, `resonance`. One table row per member and mount (R's `IntegrityResults`): tier 1 peak stress, deflection (0 for a mount), smallest safety factor over the strength rows, flags. Written beside the archive as `<run>.integrity.json` (table, every check's rows, cycle counts, notes) with `<run>.load_case.json` and `.csv`. |
